# UI/UX 设计与重构规范

本文档旨在全面分析旧版（Legacy）前端应用的功能、交互与设计，并为 V2 版本的重构提供一套统一、现代化的 UI/UX 设计规范和组件化方案。

---

## I. 现有页面功能与交互分析 (Legacy App Analysis)

旧版应用围绕聊天机器人管理，构建了一套功能全面的后台管理面板。

### 1. `/` (登录页)
- **功能概述**: 提供用户名和密码的登录入口。
- **核心交互**:
  - 用户输入凭据进行身份验证。
  - 登录成功后，系统根据用户角色（如 `admin`, `operator`）将其重定向到其权限范围内的第一个可用页面。
  - 登录失败时，显示错误提示。

### 2. `/dashboard` (仪表盘)
- **功能概述**: 系统的核心数据概览。
- **核心交互**: （当前为 `ComingSoon` 占位页面）预期应展示关键指标（KPIs）、图表和快捷入口。

### 3. `/characters` (机器人管理)
- **功能概述**: 核心功能之一，用于深度配置和管理人设（Bot Personality）。
- **核心交互**:
  - 左侧列表展示所有机器人，支持创建和选择。
  - 右侧主区域通过标签页（Tabs）对人设进行分类（如基础信息、生活偏好、人生经历等）。
  - 表单包含多种输入类型：文本、数字、以及复杂的自定义组件（如家庭成员、人生时间轴）。
  - 支持中/越双语内容输入切换。
  - 集成图片上传功能，按类别管理机器人相关图片。
  - 内嵌向量检索测试工具，用于调试和优化人设的向量匹配效果。

### 4. `/prompts` (提示词管理)
- **功能概述**: 管理和维护用于驱动大语言模型（LLM）的系统提示词（System Prompts）。
- **核心交互**:
  - 使用筛选器按“聊天阶段”（如初识、恋爱）和“AI模型”进行分类查看。
  - 以卡片形式展示每个提示词，包含名称、中/越双语内容、备注等。
  - 提示词内容支持展开/收起，以优化长文本的显示。
  - 通过模态框（Modal）进行提示词的创建和编辑。

### 5. `/knowledge` (知识库)
- **功能概述**: 另一个核心功能，管理机器人的知识体系。
- **核心交互**:
  - 分为“缩写库”和“话术库”两个主标签页。
  - 左侧栏展示知识分类，支持对分类的增删改查。
  - 主内容区展示对应分类下的知识条目。
  - 内嵌向量检索测试工具，用于验证知识库的效果。
  - 所有增删改查操作均通过模态框完成。

### 6. `/topics` (话题库)
- **功能概述**: 管理可供机器人主动发起或引导的聊天话题。
- **核心交互**:
  - 采用三级树状结构展示：`分类 -> 子分类 -> 话题`。
  - 用户可以在不同层级上进行增、删、改、查操作。
  - 交互较为复杂，需要在清晰的层级关系中维护数据。

### 7. `/users` (用户管理)
- **功能概述**: 管理后台系统的用户账户和权限。
- **核心交互**: （当前为 `ComingSoon` 占位页面）预期为标准的后台 CRUD 功能，包括用户列表、创建、编辑（分配角色）、删除等。

### 8. `/settings` (系统设置)
- **功能概述**: 配置系统的全局参数。
- **核心交互**: （当前为 `ComingSoon` 占位页面）从备份代码看，规划了通知、安全、数据、外观等设置模块。

### 9. `/test-chat` (聊天测试)
- **功能概述**: 一个面向开发和运营的强大内部测试工具。
- **核心交互**:
  - 允许选择不同的用户、会话、机器人、话题等进行组合测试。
  - 模拟真实的用户与机器人对话流程。
  - 支持发送普通消息和主动注入话题。
  - 提供消息向量化、批量处理、向量检索等高级调试功能。

## II. 侧边栏 (Sidebar) 交互分析

侧边栏是系统的主导航结构。

- **导航**:
  - 根据当前登录用户的角色动态显示可访问的页面链接。
  - 当前激活的页面链接会高亮显示。
- **主题切换**:
  - 提供“浅色”、“深色”和“系统默认”三个选项，允许用户即时切换界面主题。
- **用户信息与登出**:
  - 底部显示当前用户名和角色。
  - 提供“登出”按钮，执行退出登录操作。

## III. 现有 UI 设计系统分析 (Legacy UI Design System)

### A. 设计风格: 新拟物 (Neumorphism)

旧版界面大量采用“新拟物”风格，通过微妙的内外阴影（`box-shadow`）在扁平化的背景上营造出控件凸起或凹陷的质感。这一定义了整体的视觉语言。

### B. 颜色系统 (Color System)

系统预设了完整的浅色和深色模式调色板，通过 CSS 自定义属性（变量）实现。

**浅色模式 (Light Mode)**
| 变量名 | 色值 | 用途 |
| :--- | :--- | :--- |
| `--background` | `#f9fafb` | 页面背景 |
| `--foreground` | `#111827` | 主要文字 |
| `--component-background` | `#ffffff` | 组件背景（卡片、模态框等）|
| `--accent-background` | `#f3f4f6` | 强调背景（如输入框）|
| `--border-color` | `#e5e7eb` | 边框 |
| `--primary-blue` | `#3b82f6` | 主题色（按钮、链接）|
| `--primary-blue-hover` | `#2563eb` | 主题色悬浮状态 |

**深色模式 (Dark Mode)**
| 变量名 | 色值 | 用途 |
| :--- | :--- | :--- |
| `--background` | `#1f1f1f` | 页面背景 |
| `--foreground` | `#ededed` | 主要文字 |
| `--component-background` | `#171717` | 组件背景 |
| `--accent-background` | `#313131` | 强调背景 |
| `--border-color` | `#2e2e2e` | 边框 |
| `--primary-blue` | `#60a5fa` | 主题色 |
| `--primary-blue-hover` | `#3b82f6` | 主题色悬浮状态 |

## IV. 新版 UI/UX 重构方案 (V2 Refactoring Plan)

### A. 核心设计决策: 迁移至 Shadcn UI

**决策**: 放弃新拟物风格，全面转向基于 **Shadcn UI** 构建的现代化设计系统。

**理由**:
1.  **现代与简洁**: Shadcn UI 提供了更为主流、简洁、清晰的视觉风格，有助于提升信息密度和可读性。
2.  **可访问性**: 其组件设计遵循了无障碍设计（Accessibility）的最佳实践。
3.  **一致性**: 提供了一套设计统一、API 一致的组件，能极大提升开发效率和界面统一性。
4.  **可定制性**: 基于 Tailwind CSS，定制主题和组件样式非常灵活，可以快速建立符合我们品牌风格的视觉系统。

### B. 统一组件库清单 (Component Library)

我们将基于 Shadcn UI 建立一套标准化的组件库。

- **原子组件 (Atomic)**:
  - `Button`
  - `Input`
  - `Textarea`
  - `Select`
  - `Checkbox`
  - `Switch`
  - `Label`
  - `Icon`
  - `Badge`
  - `Avatar`

- **复合组件 (Composite)**:
  - `Card` (用于内容承载)
  - `Dialog` (模态框)
  - `Alert` / `AlertDialog` (提示/确认框)
  - `Form` (基于 `react-hook-form`)
  - `Table` (数据表格)
  - `Tabs` (标签页)
  - `DropdownMenu` (下拉菜单)
  - `Tooltip` (文字提示)
  - `Toast` (全局通知)

- **业务组件 (Business-Specific)**:
  - `Sidebar` (侧边导航)
  - `PageHeader` (页面头部)
  - `VectorTestPanel` (向量检索面板)
  - `ImageUploader` (图片上传)
  - `ExpandableContent` (可展开/收起的内容区)

### C. 统一交互模式 (Interaction Patterns)

为确保应用体验的一致性，我们将遵循以下交互模式：

1.  **CRUD 操作**:
    - **创建 (Create)**: 使用 `Dialog` (模态框) 承载创建表单。
    - **读取 (Read)**:
      - 列表数据使用 `Table` 组件，提供排序和筛选功能。
      - 卡片式数据使用 `Card` 组件。
    - **更新 (Update)**: 与创建类似，使用 `Dialog` 承载编辑表单。
    - **删除 (Delete)**: 点击删除按钮后，必须弹出 `AlertDialog` (确认对话框) 进行二次确认，防止误操作。
2.  **数据筛选**:
    - 对于列表页面（如 Prompts、知识库），在页面顶部提供统一的筛选区域，使用 `Select` 或 `Tabs` 进行分类筛选。
3.  **用户反馈**:
    - 操作成功或失败后，使用 `Toast` 在屏幕角落弹出简短的反馈信息。
    - 表单字段验证失败时，在对应输入框下方显示明确的错误提示。
4.  **长内容处理**:
    - 对于 `prompt` 或 `answer` 等可能很长的文本内容，默认只显示固定高度（如 5-6 行），并提供“展开/收起”按钮。
