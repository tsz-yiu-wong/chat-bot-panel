# 功能页面架构设计文档

## 1. 设计原则

本文档定义了构建高效、安全的功能页面（如 Characters、Knowledge、Topics 等）的架构模式。核心设计原则包括：

- **高效性**: 通过服务端预渲染、智能缓存和数据库优化确保快速响应
- **安全性**: 实施数据库行级安全策略和应用层双重权限验证
- **可维护性**: 采用清晰的分层架构，职责分明
- **扩展性**: 支持新功能和数据源的轻松集成

---

## 2. 三层架构模式

### 2.1 第一层：API Routes（权限网关层）

**职责**：
- 作为所有数据操作的统一入口点
- 执行用户身份验证和权限检查
- 调用数据访问层执行业务逻辑
- 返回标准化的API响应

**特点**：
- 每个API端点都必须进行权限验证
- 统一的错误处理和响应格式
- 支持不同HTTP方法（GET、POST、PUT、DELETE）
- 遵循RESTful设计原则

### 2.2 第二层：Server Components（数据获取层）

**职责**：
- 在服务端预获取页面渲染所需的初始数据
- 直接调用数据访问层，绕过API Routes减少网络开销
- 将数据作为props传递给客户端组件
- 提供SEO友好的服务端渲染

**优势**：
- 减少客户端的初始加载时间
- 避免客户端的loading状态和UI闪烁
- 充分利用服务器资源进行数据处理

### 2.3 第三层：Client Components（交互逻辑层）

**职责**：
- 处理用户交互和状态管理
- 通过API Routes执行增删改操作
- 实现乐观更新提升用户体验
- 管理客户端缓存和数据同步

**特点**：
- 接收来自Server Component的初始数据
- 使用React状态管理用户交互
- 通过fetch调用API Routes进行数据变更

---

## 3. 数据访问层（DAL）设计

### 3.1 核心概念

数据访问层是所有数据库操作的封装层，提供：
- 统一的数据访问接口
- 内置的权限过滤逻辑
- 性能优化（缓存、索引利用）
- 错误处理和日志记录

### 3.2 设计模式

**按功能模块组织**：
- 每个功能域（如Characters、Knowledge）都有对应的DAL类
- 静态方法提供具体的数据操作功能
- 方法命名遵循一致的约定（get、create、update、delete）

**权限集成**：
- 所有查询方法都接收用户角色参数
- 根据用户权限自动过滤返回数据
- 在数据库查询层面实施访问控制

---

## 4. 权限验证策略

### 4.1 双重验证机制

**数据库层（第一道防线）**：
- 使用Supabase行级安全策略（RLS）
- 在数据库层面强制执行访问控制
- 防止SQL注入和权限提升攻击

**应用层（第二道防线）**：
- 在API Routes中验证用户权限
- 提供细粒度的操作权限控制
- 支持动态权限判断逻辑

### 4.2 权限模型

**角色层次结构**：
- `user`: 基础用户，通常只有读取权限
- `admin`: 管理员，具有创建和修改权限
- `super_admin`: 超级管理员，具有完全控制权限

**操作类型**：
- `read`: 查看数据
- `create`: 创建新记录
- `update`: 修改现有记录
- `delete`: 删除记录

---

## 5. 向量搜索架构

### 5.1 数据库优化

**索引策略**：
- 为向量字段创建专门的ivfflat索引
- 根据数据规模调整索引参数
- 定期维护索引以保持最佳性能

**查询优化**：
- 创建专门的数据库函数执行向量搜索
- 在数据库层面结合权限过滤
- 支持相似度阈值和结果数量限制

### 5.2 搜索流程

**嵌入生成**：
- 将用户查询转换为向量表示
- 使用一致的嵌入模型确保兼容性
- 考虑缓存常用查询的向量结果

**相似度计算**：
- 使用余弦相似度进行匹配
- 支持可配置的相似度阈值
- 返回排序后的结果集

---

## 6. 性能优化策略

### 6.1 服务端优化

**数据预取**：
- Server Components预先获取页面所需数据
- 减少客户端的网络请求次数
- 利用服务器资源进行数据处理

**缓存机制**：
- 内存缓存频繁查询的结果
- 设置合理的缓存过期时间
- 支持缓存失效和更新策略

**数据库连接**：
- 利用Supabase的连接池管理
- 避免长时间占用数据库连接
- 监控连接数使用情况

### 6.2 客户端优化

**乐观更新**：
- UI立即反映用户操作结果
- 后台同步服务器状态
- 处理更新失败的回滚逻辑

**防抖机制**：
- 搜索输入使用防抖避免频繁请求
- 设置合理的延迟时间
- 取消过期的请求

**虚拟化**：
- 大数据集使用虚拟滚动
- 只渲染可视区域的元素
- 支持动态行高和复杂布局

---

## 7. 错误处理和监控

### 7.1 错误分类

**权限错误**：
- 401 Unauthorized: 用户未登录
- 403 Forbidden: 用户无权限执行操作
- 统一的错误响应格式

**数据错误**：
- 404 Not Found: 请求的资源不存在
- 422 Unprocessable Entity: 数据验证失败
- 500 Internal Server Error: 服务器内部错误

### 7.2 监控策略

**性能监控**：
- 记录API响应时间
- 监控数据库查询性能
- 跟踪向量搜索效率

**安全监控**：
- 记录权限验证失败事件
- 监控异常访问模式
- 实施访问频率限制

---

## 8. 扩展性考虑

### 8.1 新功能集成

**模块化设计**：
- 每个功能模块独立开发和部署
- 统一的接口规范便于集成
- 支持功能的渐进式增强

**数据源扩展**：
- DAL层支持多种数据源
- 统一的数据访问接口
- 支持数据源的热切换

### 8.2 性能扩展

**水平扩展**：
- 无状态的API设计支持负载均衡
- 数据库读写分离
- 缓存层的分布式部署

**垂直扩展**：
- 数据库连接池优化
- 内存缓存容量调整
- 服务器资源配置升级
