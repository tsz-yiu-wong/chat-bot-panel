# PRD 摘要

> **目标**: 本文档旨在定义“机器人即服务”平台的核心产品需求，作为后续技术设计与开发的统一依据。

## 1. 目标与非功能性约束

### 1.1. 核心目标
- **业务目标**: 构建一个健壮、可扩展的“机器人即服务”平台，能够支持外部脚本进行 24/7 的自动化、实时聊天交互。
- **技术目标**: 设计一个职责清晰、高性能的后端架构，同时为内部运营人员提供一个流畅、易用的数据管理后台。

### 1.2. 非功能性约束
- **高可用性**: 核心聊天引擎必须保证 24/7 可用，以支持不间断运行的外部脚本。
- **高性能**:
    - 外部聊天 API 响应需足够迅速，以满足同步调用的需求。
    - 内部管理后台的 CRUD 操作需快速响应，提供流畅的用户体验。
- **可维护性**: 系统架构需模块化、低耦合，便于独立开发、测试、部署和迭代。
- **安全性**: 用户数据和访问权限需得到严格控制，系统关键操作需有权限校验。

## 2. 关键用户与核心场景

| 关键用户 | 核心场景 | 描述 |
| :--- | :--- | :--- |
| **外部自动化脚本** | 实时同步聊天 | 脚本作为聊天发起方，通过 API 调用 Python 核心引擎，发送消息并同步等待 AI 回复，用于执行自动化任务。 |
| **后台管理员** (`admin`/`super_admin`) | 后台配置管理 | 管理员登录前端管理后台，对系统数据进行增删改查(CRUD)操作，包括角色人设、知识库、系统 Prompt 等。 |
| **普通用户** (`user`) | 查看面板数据 | （如果适用）普通用户登录后台，只能查看授权范围内的数据，没有写入权限。 |

---

## 3. 业务流程

### 3.1. 同步聊天流程
1.  **外部脚本**向 **Python 核心引擎** 发起一个包含用户消息和角色 ID 的同步 `POST` 请求。
2.  **Python 引擎**从 **Supabase 数据库**拉取所需的所有上下文数据（如角色人设、知识库、历史聊天记录、Prompt 等）。
3.  引擎根据内部业务逻辑，动态构建最终的 Prompt。
4.  引擎调用**大语言模型 (LLM)**，并等待其返回生成的回答。
5.  引擎将本次的交互记录（用户消息和 AI 回答）保存回 **Supabase 数据库**。
6.  引擎将从 LLM 收到的回答直接作为响应，同步返回给**外部脚本**。

### 3.2. 后台配置流程
1.  **后台管理员**在**前端管理后台**（React App）上执行操作（如编辑一个角色人设）。
2.  前端应用向 **Next.js 管理 API** 发起一个请求（如 `UPDATE`）。
3.  **Next.js API** 首先验证管理员的用户身份和操作权限。
4.  验证通过后，API 向 **Supabase 数据库**执行相应的 CRUD 操作。
5.  数据库将操作结果返回给 **Next.js API**。
6.  API 将格式化后的成功或失败信息（通常为 JSON）返回给**前端应用**，前端据此更新 UI。

## 4. 业务对象与核心规则

### 4.1. 核心业务对象
- **用户 (`User`)**: 分为 `user`, `admin`, `super_admin` 三种角色，拥有不同权限。
- **角色人设 (`Character`)**: AI 机器人的身份定义，包含丰富的背景资料。
- **知识库 (`Knowledge`)**: 用于支持 AI 回答的结构化信息，包含“缩写”和“话术”两类。
- **话题库 (`Topic`)**: 预设的话题，用于引导或触发对话。
- **提示词 (`Prompt`)**: 用于指导 LLM 生成内容的系统级指令。
- **聊天会话 (`Chat Session`)**: 一次完整的对话过程，包含多条聊天消息。
- **聊天消息 (`Chat Message`)**: 会话中的单条消息，区分 `system`, `user`, `assistant` 角色。

### 4.2. 核心业务规则
- **权限规则**:
    - 只有 `admin` 和 `super_admin` 角色才能执行写入操作（创建、更新、删除）。
    - 普通 `user` 角色只能读取数据。
- **数据规则**:
    - 所有核心数据的删除均为**软删除**，只更新 `is_deleted` 标记，不物理删除。
    - 核心内容（人设、知识库、聊天消息）的创建和更新会自动触发**向量化**流程。
- **交互规则**:
    - 聊天引擎与外部脚本的交互是**同步**的，一次请求必须对应一次完整的处理和返回。
    - 管理后台与 Next.js API 的交互是**异步**的。
